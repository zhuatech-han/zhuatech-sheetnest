Docker Compose包含MySQL8.4、Java21服务和Nginx；只前端8132绑定127.0.0.1。准备Docker／Compose、Python3.11+。源码调试另需Java21、Maven3.9、Node24.19.0及npm11；依赖版本锁定。后端镜像全量测试，前端镜像格式、静态检查、测试和生产构建。独立数据库会自动执行V1／V2，JPA仅校验。

```bash
python3 scripts/init-env.py
docker compose config --quiet
docker compose up --build -d --wait
# 端口占用时使用同一项目和被忽略.env，覆盖公开变量
WEB_PORT=18132 docker compose up -d --wait
```

.env随机且0600，勿发布或复制生产口令到公开仓库。.env.example仅列配置名称。登录admin，密码读取ADMIN_PASSWORD；账号只在空库初始化，修改环境变量不重置已有密码。DATABASE_URL／DATABASE_USER／DATABASE_CATALOG供源码开发连接使用；Compose内置连接，不需发布数据库端口。

升级先备份并在独立环境验证。迁移文件固定在backend/src/main/resources/db/migration；新增版本，不能修改已发布文件或关闭Flyway验证。日志在本机阅读与脱敏，不能公开完整错误载荷或凭证。

## 备份与独立恢复

```bash
mkdir -p private-backups
chmod 700 private-backups
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --no-tablespaces --set-gtid-purged=OFF "$MYSQL_DATABASE"' > private-backups/sheetnest.sql
chmod 600 private-backups/sheetnest.sql
```

备份含账号散列和业务数据，只保存在受限私有目录。恢复到独立空卷，使用不同项目名和端口，不覆盖原数据库：

```bash
WEB_PORT=18132 docker compose -p sheetnest-restore build
WEB_PORT=18132 docker compose -p sheetnest-restore up -d --wait mysql
# 已确认目标为独立恢复项目
WEB_PORT=18132 docker compose -p sheetnest-restore exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' < private-backups/sheetnest.sql
WEB_PORT=18132 docker compose -p sheetnest-restore up -d --wait
# 在包含同一隔离验收状态的本机目录验证恢复；不是生产写入
TEST_URL=http://127.0.0.1:18132 python3 scripts/smoke.py --verify
```

Compose默认卷按项目名隔离。恢复验证应核对数据库、Flyway版本、健康、登录、完整业务JSON、指定岗位及成功UUID响应；恢复之后无需再次初始化业务。

停止用docker compose down保留卷；仅确认当前独立测试资源可丢弃才down -v。不要清理其他项目容器或卷。验收smoke.py会创建明确TEST记录，只能在隔离回环实例及新库执行。

对外服务由部署方配置可信HTTPS、COOKIE_SECURE=true、受控代理转发头、网络访问策略和最小权限。默认会话在Java进程内，重启需重新登录；数据库事实持久化。未提供高可用、多租户、自动外部备份或机器控制。
